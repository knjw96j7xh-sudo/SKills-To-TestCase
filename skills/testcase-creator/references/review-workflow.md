# 评审工作流

## 1. 评审维度选择

读取 `.testcase-assets/review-expectations-index.md`，按分类展示全部评审点。接受多个编号或“全部”，再按 UX、DATA、COMP、EXEC、BUG、SEC、PERF 等分类分组。

```text
【阶段 4 — 评审点选择】
请选择本次评审维度（多个编号用逗号分隔，也可输入“全部”）：

>> 用户体验
  [UX-01] [描述]

>> 数据一致性
  [DATA-01] [描述]
```

## 2. 评审范围

- 第 1 轮：全量评审，展开所有用例完整字段。
- 第 2 轮及以后：只展开本轮新增或修改用例；已有用例仅提供用例 ID、测试点、场景类型和优先级。
- 主 agent 跟踪 `review_round`，初始值为 1。

## 3. 分维度评审（并行优先，串行降级）

优先：每个维度启动一个独立 subagent，所有维度同时执行。  
降级：当前环境无法并行 subagent 时，在同一会话内按维度**串行**评审，输出格式与合并规则不变。

每个维度任务只接收：

- 需求与设计要素摘要及已确认差异结论；
- 当前轮评审范围内的用例；
- 该维度的评审点，不包含其他维度。

使用以下任务模板：

```text
你是一名独立测试评审专家，专注于“{维度名称}”。
请基于提供的评审点逐条审查用例。

## 需求与设计要素
[摘要和差异结论]

## 评审维度
[仅该维度评审点]

## 待评审用例
[首轮全量；后续为已有用例摘要和新增/修改用例详情]

请输出：
1. 评审报告表格：评审点 / 是否覆盖 / 分析说明 / 建议补充用例
2. 建议补充用例完整行（如有）
3. 本维度结论
```

## 4. 合并规则

| subagent 结论 | 合并处理 |
|---------------|----------|
| `[OK]` | 标记“已覆盖” |
| `[FAIL]` | 标记“未覆盖” |
| `[WARN]` | 标记“需关注” |
| 多维度提出相同用例 | 去重合并并标注来源维度 |

汇总内容必须包含各维度结论、未覆盖项和建议补充用例。

## 5. 文件输出

每轮写入 `<运行目录>/1-评审报告-第N轮.md`，包含详细报告、合并结论、建议补充用例及本轮 token 统计：

```markdown
## Token 消耗（本轮）
| 项目 | 数值 |
|------|------|
| 评审轮次 | 第 N 轮 |
| 评审模式 | 全量 / 增量 |
| 并行维度数 | X 个 |
| 评审用例数 | X 条 |
| 本轮 token 消耗 | 约 XXX |
| 会话累计 token | XXX |
```

`1-评审记要.md` 只保留合并后的最终用例表，不得混入评审过程。

## 6. 用户决策与循环

展示发现数量和建议数量，再询问：

```text
A. 接受所有补充（合并后继续评审）
B. 仅接受共识项
C. 部分接受（指定编号）
D. 手动修改
E. 忽略，进入阶段 5
```

- 选择 A/B/C/D：合并被接受的修改，`review_round += 1`，进入增量评审。
- 选择 E：结束评审并进入阶段 5。
- 每轮都必须由用户作出决策，不得自动宣告评审通过。
